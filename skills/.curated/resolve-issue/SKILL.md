# Resolve Issue

把 issue 当作问题入口，不当作正确答案。先验证问题和验收标准，再实现最小完整修复，最后通过 PR/MR 交付。

## 与其他 skill 的关系

- 实现代码时使用 `$development`，由它按改动范围加载前端、后端和语言 reference，并遵循仓库自己的指令。
- 开发中提交 issue 改动时使用 `$commit` 的仅提交模式，避免提前清理当前现场。
- 只有用户要求完整闭环或明确授权合并时才使用 `$merge-pr`；只创建 PR/MR 时在该边界停止。
- 未进入 `$merge-pr` 时，本流程结束前使用 `$commit` 默认收口；进入后由 `$merge-pr` 负责最终收口，不重复调用。

## 工作流

执行前读取 [issue-checklist.md](references/issue-checklist.md)。

### 1. 读取并验证 issue

按 checklist 读取 issue、讨论、附件和关联请求，确认权威验收条件并检查重复、已有修复或默认分支现状。已有健康 PR/MR 完整覆盖时不重复实现；关键来源冲突或需求歧义足以改变方案时暂停澄清。

### 2. 建立基线与隔离环境

读取仓库指令并建立最新 base；需要远端交付时提前验证平台登录、仓库映射和所需权限。在不覆盖已有改动的前提下创建 issue 专用分支，必要时使用独立 worktree，并记录本流程创建的现场。

### 3. 复现与设计修复

建立失败基线并追到根因；按 `$development` 实现最小完整修复，涉及公共契约、数据、权限或用户行为时处理兼容、迁移和回滚。

### 4. 实现与验证

补充能证明问题已解决的测试并按风险验证失败基线、正常路径和回归风险；独立问题只记录，不夹带修复。

### 5. 提交与创建 PR/MR

使用 `$commit` 仅提交模式检查并提交当前 issue 改动。远端交付前重新读取 issue、默认分支和相关 PR/MR；确认仍需交付后推送并创建关联请求，正文按 checklist 记录根因、方案、验证、风险和回滚。

### 6. 评审与合并

用户授权合并时调用 `$merge-pr`，并按独立评审标准处理 CI、review、冲突和最终合并；只要求修复或创建 PR/MR 时在指定边界停止。等待或恢复时重新读取远端状态，不沿用旧 SHA、检查或 review。

### 7. 更新 issue 与清理

只有修复进入目标分支后才确认或更新 issue 关闭状态。未调用 `$merge-pr` 时，使用 `$commit` 默认收口并把仍需继续的 issue/PR 现场标为活跃；已调用时复用其收口结果。

## 停止条件

遇到以下情况时保留现场并报告：

- issue 无法访问、已过期、重复或验收条件互相冲突。
- 无法复现且缺少继续调查所需信息。
- 修复需要超出 issue 范围的产品决策、数据迁移或破坏性变更。
- CI、权限、required review 或外部依赖阻塞交付。
- 发现 secret、供应链风险或高影响安全问题。

停止或交接前按上述所有权调用 `$commit` 或复用 `$merge-pr` 的收口结果；只把恢复当前 issue 必需的 AI 现场标记为活跃，用户或归属不明现场保持原样。

## 最终回复

必须包含：

- issue 与 PR/MR URL、根因和最终行为
- branch/worktree、提交 SHA、目标分支和合并状态
- 修改范围与实际运行的验证
- 未运行检查、已知风险和回滚方式
- issue 关闭状态
- 本流程创建、删除和保留的现场及本地仓库最终状态
- 使用 `$commit` 或 `$merge-pr` 的交付与收口结果
