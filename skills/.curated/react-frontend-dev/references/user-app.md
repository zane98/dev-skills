# User App Rules

在用户端、官网、活动页、内容产品、SaaS 前台或面向终端用户的 React 应用中，默认采用以下策略：

- 组件优先级：项目已有组件 > `shadcn/ui` > 新建自定义组件
- 表单优先级：项目已有封装 > `react-hook-form + zod`
- 视觉与体验质量要求较高时，同时使用 `ui-ux-pro-max`
- 保持组件语义化和可组合，避免将业务逻辑硬编码到基础 UI 组件中
- 表单、弹窗、抽屉、下拉、日期选择、Toast 等优先用成熟组件组合，而不是裸写基础 DOM
- 页面应明确区分加载态、空态、错误态、无权限态和成功反馈
- 用户交互要有即时反馈，异步操作需提供禁用、loading、toast 或 inline status
- 返回按钮、取消按钮、关闭按钮的行为必须清晰且一致
- 列表页的筛选、分页、排序默认同步到 `search params`
- 表单 schema、默认值、提交映射和字段级错误应成体系管理
- 关键路由或高风险页面区块可使用 `Error Boundary` 做局部隔离，但不要把它当默认视觉兜底

适合抽取的公共内容：

- 通用表单字段组件
- 列表筛选栏、分页工具栏、搜索框
- Skeleton、Empty、ErrorBoundary、Result 状态组件
- 通用弹窗、确认流、上传组件、富文本外壳、图表外壳

不推荐的做法：

- 用户端表单到处手写校验和提交流程
- 列表页状态只存在内存里，刷新和返回后全部丢失
- 为了一个简单页面引入另一套并行 UI 风格
- 明明已有现成组件，却重新写一套交互和样式
- 直接依赖原生弹窗作为正式交互
