# Monorepo Rules

当仓库中存在多个 React 应用、用户端与后台并存、或多个包共享前端能力时，使用以下策略：

- 优先抽取共享 `api` 层、`query` 配置、鉴权逻辑、通用 hooks、基础组件和设计 token
- 共享层应放在稳定包或公共目录中，不要在多个应用中复制同一份实现
- 统一接口请求客户端、错误处理策略、鉴权注入和缓存策略
- 将 `queryKey`、请求函数、数据类型和常见 selector 放到可复用层，避免每个应用各写一套
- 对跨应用共用组件，先抽取无业务耦合的基础能力，再按应用侧包装业务组件
- 用户端与管理后台可以共享请求基础设施，但不应强行共享不适配的视觉组件
- 如果一个包只被一个应用短期使用，不要过早抽象；共享应以稳定复用为前提

建议优先共享的内容：

- `packages/api` 或等价请求层
- `packages/query` 或 query 初始化与辅助封装
- `packages/ui` 中与品牌无强耦合的基础组件
- `packages/utils` 中的日期、格式化、权限、下载、文件处理等工具
- 类型定义、错误模型、响应模型

抽取共享层时检查：

- 依赖方向是否单向清晰
- 包边界是否避免循环依赖
- 公共 API 是否足够稳定
- 是否真的减少重复，而不是制造额外维护成本
