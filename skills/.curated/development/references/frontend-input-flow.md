# Frontend Input Flow

新增或重做创建、编辑、配置、审批等输入流程时使用；短小字段修复不需要读取。

## 选择载体

- 先按用户任务、耗时、信息分组、上下文依赖、深链/刷新/返回需求、取消恢复和目标视口选择载体，不按字段数量机械决定。
- modal 用于短小、原子、无需离开当前上下文的确认或输入；drawer 用于需要边操作边参照当前页面的中等复杂任务。
- 信息多、耗时长、需要深链/恢复、附件、复杂校验或跨区联动时使用独立页面。只有步骤存在真实依赖或一次展示造成明显认知负担时才拆成分步流程。
- 预计桌面 modal/drawer 主体需要长距离滚动，或背景被遮罩后无法有效参照时，优先重组内容或升级为页面，不能靠压缩字号和间距硬塞。
- 移动端按平台习惯转换为全屏 dialog、sheet 或页面；处理软键盘、安全区、单一滚动容器、焦点和主要操作可达。

## 提交与恢复

- 复杂、高影响且难以整体复核的表单，在最终 mutation 前提供只读预览或等价确认；短小、低风险、易撤销的表单不增加仪式步骤。
- 预览使用同一份已校验快照，允许返回修改并保留输入；确认失败停留在可核对、可重试状态，不建立第二套可编辑表单。
- 已采用预览/确认的流程中，校验失败不得进入确认，最终 mutation 由确认动作触发；直接编辑保存的低风险流程不额外加确认。两类流程提交失败都保留输入与恢复路径。
- 提交成功进入结果或详情后，历史栈不应重新暴露已经完成的填写/确认页；从既有详情进入编辑时返回原详情。

## 布局与验证需求

- 操作区优先随内容自然排布或在滚动容器内 sticky；必须覆盖内容时由同一尺寸来源驱动定位和底部避让。
- 验证短内容、长内容、窄视口、缩放、软键盘和安全区；滚动到底后最后一项、错误和主要操作必须完整可见可点。
- 在运行态覆盖校验失败、返回修改、提交中、成功、服务端失败和重试；输入期异步反馈按 [前端核心](frontend-core.md) 检查几何稳定性，确认焦点、滚动位置和操作锚点稳定。
