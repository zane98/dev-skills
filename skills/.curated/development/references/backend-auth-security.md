# Auth Security

## 鉴权与权限

- 登录态、用户身份、角色和权限来源必须可信；鉴权失败或上下文不完整时默认拒绝。
- 权限判断放后端服务层或统一中间件；前端隐藏按钮不算权限。
- 资源级权限要校验资源归属，不能只校验“有这个角色”；多租户读写必须使用服务端可信租户上下文，不能直接相信请求中的 tenantId。
- token/session 要明确签发、过期、刷新、撤销和登出语义；权限变化后不能让旧会话无限有效。
- 管理后台操作要考虑审计：谁在什么时候改了什么。

## 输入与输出

- 所有外部输入都要校验：body、query、path、header、文件、回调和队列消息。
- SQL、命令、路径、模板、正则和反序列化都不能拼接不可信输入。
- 用户可控 URL、回调地址或导入源必须限制协议、目标和重定向，防止 SSRF 访问内网或云元数据。
- 返回数据要做字段控制，避免泄露手机号、token、密钥、内部备注和系统字段。
- 文件上传检查类型、大小、存储路径、访问权限和病毒/恶意内容风险。

## 请求保护

- 登录、验证码、找回密码和高成本/高风险接口按风险设置限流、防爆破和审计。
- Cookie 登录明确 `Secure`、`HttpOnly`、`SameSite` 和 CSRF 防护；CORS 使用明确来源，携带凭证时禁止通配来源。
- 对外 webhook/callback 校验签名、时间戳或 nonce，并限制重放窗口。

## 密钥与敏感数据

- 密钥、token、数据库密码和第三方凭证只能走配置或密钥管理，不能进代码。
- 日志中禁止打印敏感字段；必要时脱敏。
- 密码使用项目已有身份服务或成熟密码哈希库及安全参数；禁止可逆存储、通用哈希和自制密码学。
