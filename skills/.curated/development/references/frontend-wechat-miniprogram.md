# WeChat Mini Program

用于所有微信小程序任务；与 Taro、uni-app 或原生小程序规范组合使用。

## 路由与认证边界

- 微信小程序的页面注册表和导航栈不是 Web 的嵌套路由树，不能假设存在全局 `beforeEach`、父路由 layout 或当前路由 `Outlet`。
- 导航 API wrapper 或拦截器只能改善主动跳转体验，不能单独承担页面准入；冷启动、分享、扫码、tab 切换和外部唤起都可能直接进入目标页面。
- 全局 App 负责会话初始化、Provider 和应用生命周期。公开与受保护页面并存时，在框架支持的最外层页面注册/export 边界阻止受保护内容挂载，并让未登录、取消、失败、重试和登录后恢复目标均可操作。
- 客户端准入不替代服务端授权；敏感查询和写入始终由服务端按可信身份和资源范围校验。

## 反馈与通知

- 遵循项目明确的提示长度与样式约定。未规定时，toast 用于短暂、轻量、无需后续操作的信息；长文案、字段错误或需要用户处理的结果用行内提示、状态区或对话框。
- 按实际组件、语言、字号与展示时长判断可读性，不把固定字符数当平台限制；不截断关键信息来适配 toast。技术错误转成完整、可执行的用户语义。

## 底部 Drawer 与 TabBar

- 在含底部 TabBar 的页面打开底部 Drawer 时，必须在 Drawer 入场前隐藏 TabBar；使用原生 TabBar 时调用平台隐藏能力，使用自定义 TabBar 时由统一可见性状态控制，不能只用遮罩或 `z-index` 把 TabBar 盖住。
- Drawer 取消、确认、遮罩点击、手势关闭、系统返回、请求失败、页面隐藏或卸载等所有退出路径都必须恢复 TabBar。隐藏与恢复保持幂等并集中在 Drawer/Page 生命周期边界，处理快速开关和异步回调竞态，不能让 TabBar 永久消失或在退场动画中提前闪回。
- Drawer 入场期间保持 TabBar 隐藏，完成退场后再恢复；同时处理底部安全区、遮罩层级、背景滚动和触控穿透，确保隐藏后的 TabBar 区域不会残留可点击热区。
- 分别在原生和自定义 TabBar 的实际命中形态上验证打开、各关闭路径、连续快速开关、切页和返回；截图只能证明静态层级，必须用运行态 smoke 证明 TabBar 显隐时序正确。

## 运行时兼容

- 把微信基础库 API、JavaScript 引擎能力和浏览器 Web API 视为三套边界。配置 `libVersion`、启用 ES6 编译或在开发者工具 / H5 中运行成功，都不能证明真机存在 `Intl`、`AbortController`、`globalThis`、`Object.fromEntries`、`Promise.allSettled`、`Array.prototype.at / flat / flatMap` 等能力。
- 引入或升级日期、时区、国际化、请求缓存及其他运行时依赖时，检查实际入口、插件和最终小程序产物，不根据库名或核心包能力推断间接依赖。日期库核心与 timezone / locale 插件的依赖可能不同；只有产品时间语义明确为固定偏移且不需要时区换算时，才使用固定 offset 简化实现。
- 项目自有代码能清晰改写的新内置方法优先改写；第三方依赖确实需要且目标运行时可能缺失的能力，使用集中、最小、幂等的兼容层。不要无边界引入整套浏览器 polyfill。
- 兼容层必须早于 Query Client、状态容器、插件和首个消费者初始化。为缺失全局对象提供 `typeof` 守卫和目标平台兜底；禁止先直接读取可能不存在的 `globalThis`，再尝试安装 polyfill。
- 微信 API 使用项目支持的能力检测或 `wx.canIUse` 并提供降级；不要把微信 API 不支持与 JavaScript 内置对象缺失混成同一种问题。

## 构建与发布门禁

- 用户要求“启动 dev”“打开看看”或等价运行验收时，必须同时确认 watch 进程存活、开发者工具加载了当前产物、模拟器冷启动后首屏无运行时异常；构建完成或 CLI 返回 `open` 不能单独作为运行成功证据。
- 实现 `tabBar` 前先对照产品事实和设计稿核对入口数量、顺序、文案、图标语义、选中态与真实页面落点，不能根据现有路由自行重排信息架构。仅存在页面路径和标签不代表导航视觉已完成。
- 使用原生 `tabBar` 时逐项核对 `iconPath` 和 `selectedIconPath` 的配置与资源格式；再确认资源真实进入构建产物并满足单文件限制。设计要求字重、徽标或其他原生配置无法表达的状态时，使用自定义 `tabBar`，并在目标平台验证适配，不能静默降级成只换颜色。
- 使用自定义 `tabBar` 时先从代码核对各 tab 独立组件实例、路由和内容避让；再验证选中状态、冷启动、`switchTab`、触控区和运行时安全区，检查组件产物和本地图标是否被错误内联。
- 显式定义并版本化 JavaScript 构建目标和开发基础库版本；两者是团队编译 / 调试基线，不替代运行时兼容策略，也不等于公众平台配置的客户端最低基础库版本。
- 不只扫描源码，还要检查用户指定环境的真实 `mp-weixin` 产物中的危险内置方法、locale formatter、未转译新语法和预期兼容安装器；第三方依赖生成的 `vendor.js` 纳入检查。
- 为确认过的缺失能力增加回归测试：临时移除对应全局或静态方法，验证模块仍可加载、兼容层会在消费者之前安装，并覆盖 fulfilled / rejected 等边界语义。
- 按范围执行目标小程序的 typecheck、定向测试和用户要求的发布构建；再使用用户指定的 Android/iOS 微信真机 smoke 冷启动、登录和首个数据页面。开发者工具预览不能替代真机验证，未经要求不自动扩大平台范围。
- 无法从仓库确认公众平台最低基础库设置或真机结果时，明确列为发布前外部检查，不声称已由代码验证。

## 包体预算

- 以当前目标平台官方限制和项目 CI 预算为准，区分主包、分包与静态资源；项目可设置更严格预算，不把个人经验值当平台硬限制。
- 从目标构建产物判断体积与增长余量，再选择按需导入、分包或远端资源；需本地引用的原生配置资产保留本地。
- 发布构建按实际预算校验；未构建或未确认平台限制时，说明未验证范围，不声称满足发布条件。
