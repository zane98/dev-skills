# 产品与代码文档同步

本文件只决定何时更新哪份权威文档。产品目标与方案合理性由 [产品与交互判断](product-and-interaction.md) 负责；沿用项目现有文档结构，不默认另建 L1/L2/L3、PRD 或 ADR 体系。

## 唯一归属

| 内容 | 归属 |
| --- | --- |
| Agent 工作方式、项目命令、模块职责和稳定工程边界 | AGENTS.md |
| 用户场景、目标结果、产品规则、流程、状态/权限、重要取舍和验收行为 | 现有产品文档 |
| 长期技术决策的背景、替代方案、兼容迁移与恢复 | 项目已有架构文档或 ADR/RFC |
| 真实实现和可执行契约 | 源码与测试 |
| 独立缺陷与后续工作 | 项目问题跟踪系统；按 [Issue 分流](development-issue.md) |

文档保存仍能解释当前行为的原因和约束，不保存聊天经过、逐轮验证和已失效争论。代码当前行为与产品预期冲突时先判断目标契约，不把任一方自动当作正确答案。

## 何时同步

- 用户目标、业务规则、流程、权限、状态、验收行为或对外契约改变：更新对应产品事实与受影响实现。
- 长期架构边界、技术决策、运行方式或模块职责改变：更新已有工程/架构文档；仅产品文档已经记录该方案或 Code Map 且需要变化时同步对应内容。
- 新增明确且长期维护的产品能力、没有等价文档：创建最小功能说明，在现有导航中登记。没有现成总图时，只有确实需要跨能力导航才创建索引。
- 精确修复既有定义、内部重构、格式和无语义视觉微调：不为一次代码变动新增产品记录。
- 文档内的入口或 Code Map 已记录且发生变化：修正实际引用；不要求所有内部文件都登记。
- HTML 模型与产品文档表达同一事实时，指定一份权威来源，另一份引用或保留必要投影，避免双份完整定义漂移。

## 最小内容

需要新增功能说明且没有项目模板时，仅保留有实际内容的部分：

- 用户、触发场景、原问题与当前路径。
- 目标结果、范围与非目标。
- 主流程、关键状态/权限与失败恢复。
- 最终方案、关键理由、必要边界和仍待验证的假设。
- 可观察的验收行为、主要实现入口。

不为填满模板制造空章节。执行计划只跟踪实现产出与依赖，检查结果留在当前对话、PR 或 CI；测试与外部写入按 [执行边界](execution-boundaries.md) 授权。

## 完成核对

- 产品事实、公开契约和长期架构说明没有因本次修改过期。
- 新增行为有可追溯的用户场景和理由；未验证假设没有被写成确定事实。
- 引用的入口有效，文档与目标实现一致；AGENTS.md 没有混入产品细节或任务流水。
