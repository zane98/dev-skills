# 跨层契约

用于事实跨客户端、API、服务、存储或下游传递，以及判断真实链路完成度。只追踪受影响事实，不为无关层生成表格。

## 沿事实追踪

明确权威来源、写入者和必要消费方，核对两条路径：

- 写入：用户入口 → 客户端状态 → payload → API 校验/权限 → 领域与存储。
- 读取：存储 → 查询/mapper/输出 DTO → 详情、后台、其他端或下游。

每个经过的边界保持同一字段、类型、单位、空值、枚举、错误和权限语义；兼容窗口内旧消费者仍能正确工作。纯计算响应不要求持久化，不适用的层直接省略。

常见断链是表单未保存值、序列化丢字段、输入接收但未落库、查询/DTO 未返回、消费方仍读旧缓存。按真实边界取证，避免逐层重复证明同一事实。

金额、权限、支付、身份和状态结论由可信服务端事实产生。乐观更新、本地草稿、接口成功响应或截图均不能单独证明持久化和回读；换账号、刷新或重放后仍应满足契约。

## 角色与会话变化

授予、移除或切换身份时，连通权威角色关系、依赖业务档案、授权操作入口、会话回读、客户端准入和缓存清理。后端关系与撤销规则见 [认证与安全](backend-auth-security.md)，前端状态归属见 [前端核心](frontend-core.md)。

需要人工管理的转换应有可发现且有权限的入口；系统自动转换不因此新增后台按钮。多身份用户能选择可用身份，单身份不制造额外流程。切换后的凭证、路由与缓存必须对应新作用域，旧身份数据不残留。

声称多角色链路已验证时，给出管理变更持久化、目标账号刷新会话、切换身份、重新加载和旧作用域拒绝/清理的路径证据；只改 DTO、隐藏菜单或通过单个 service 测试时说明尚未验证的环节。

## 规模与查询

列表、搜索和聚合涉及规模、排序或关联时按 [数据建模](backend-data-modeling.md) 检查结果粒度、查询成本及分页前过滤；有界小集合不强制分页。按需要验证真实数据库往返、调用方兼容、拒绝路径和并发，检查选择遵循 [Development](../SKILL.md)。

## 完成表述

分别说明实现覆盖与验证覆盖；必要时用事实表：事实、生产/消费路径、直接证据、缺口。

- `real`：实际应用路径已接通，且有覆盖关键边界的测试或联调证据；不等于已部署生产。
- `mock-only`：来自 fixture、mock adapter 或隔离开发数据。
- `pending-backend`：目标契约已明确，可信服务端链路尚未完成。
- 已实现但缺运行证据时直接写“已实现，未验证该链路”，不误归为缺实现或 `real`。

缺少必要环节时报告部分完成和具体断点。前端先行可以完成隔离实现，但不能把预览或假成功称为真实入库；工程状态如何呈现给产品用户遵循项目规则。
