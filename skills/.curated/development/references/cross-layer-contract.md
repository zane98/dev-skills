# Cross-Layer Contract

当字段或业务事实跨越客户端、API、服务、存储和其他消费端，或者需要判断功能是否真实完成时，使用本参考。按任务组合 `frontend-core.md`、`backend-api-contract.md` 和 `backend-data-modeling.md`，不要在这里重复各层实现规范。

## 先确定事实边界

- 明确业务事实的生产方、可信来源、写入入口、读取入口和全部必要消费方。
- 写清请求、响应、字段类型、必填与空值语义、枚举、错误、权限和兼容策略，再让各层实现同一份语义。
- 区分目标契约与当前实现。缺少真实后端时标记 `pending-backend`；隔离开发或测试数据标记 `mock-only`，不能让页面自行发明字段或业务结论。
- 金额、权限、审核、支付、资金、身份和状态机结果必须来自可信服务端事实，不能由客户端默认值、本地缓存或界面状态补齐。

## 追踪写入与读取链路

对新增、修改或有疑问的业务字段建立最小事实表；不适用的环节明确标记 `n/a`，不要机械制造层级。

| 环节 | 需要证明的事实 |
| --- | --- |
| 用户入口或展示 | 字段确实被输入、选择或需要展示 |
| 客户端状态 | 表单、view model 或领域状态保存了正确类型和空值 |
| 出站请求 | payload、序列化、枚举和单位符合目标契约 |
| API 输入 | schema/DTO、handler、校验和权限真实接收该字段 |
| 领域与存储 | service、model、migration、事务和历史数据策略承接该字段 |
| API 输出 | 查询、mapper、响应 DTO 和序列化返回真实持久化结果 |
| 必要消费方 | 详情、审核、后台、其他客户端或下游服务使用查询结果回显 |

分别验证两个方向：

1. 写入链路：入口 -> 客户端状态 -> payload -> API 输入 -> 领域与存储。
2. 读取链路：存储 -> 查询与输出 DTO -> 必要消费方。

提交页预览、乐观更新或本地草稿只能证明客户端状态，不能证明写入成功；写入成功但查询未返回，或者查询已返回但必要消费方未使用，也只能算部分完成。

## 判断实现状态

按真实证据标记每个关键字段：

- `real`：生产路径中的写入、持久化、读取和必要消费方均已接通，并有直接测试或联调证据。
- `mock-only`：只由 fixture、mock adapter 或隔离开发数据提供。
- `pending-backend`：目标契约已明确，但可信服务端或持久化链路尚未实现。
- `n/a`：该环节经确认不适用于当前事实，例如纯计算响应不需要持久化。

不要因为类型已声明、页面能预览、接口返回成功、本地刷新前可见或单个服务测试通过，就自动标记为 `real`。

## 检查常见断链

- 页面有字段，但表单状态或 payload 丢失。
- 客户端类型有字段，但 API 输入 DTO、校验或 mapper 没有。
- API 接收字段，但 service、model、migration 或事务没有保存。
- 后端已经保存，但查询、输出 DTO 或序列化没有返回。
- API 已返回，但详情、审核、后台或其他必要消费方仍读本地缓存、旧字段或硬编码默认值。
- mock、本地存储、乐观状态或假成功结果被误当成业务完成事实。
- 换账号、换设备、冷启动或重新查询后结果丢失或串号。

## 性能与数据成本

链路涉及列表、搜索、筛选、详情、导出、关联数据或大字段时，同时读取 `backend-data-modeling.md` 并核对：

- 是否分页、限制结果规模并只返回需要字段。
- 是否存在循环查询、序列化隐式查询、N+1 或同批数据重复读取。
- 高频过滤和排序是否有合适索引与可接受查询计划。
- 大 JSON、文档、附件或导出是否需要投影、分块、流式或异步处理。

性能优化如果明显增加一致性、迁移或维护成本，先说明可验证收益、方案代价和回滚方式。

## 验证与完成门禁

- 优先使用契约测试、handler/service 集成测试、真实数据库往返测试和关键流程 smoke/E2E，证明变化实际跨越边界。
- 覆盖正常、空值、非法枚举、权限、服务端错误、重复提交和旧调用方兼容；高风险状态继续覆盖幂等、事务和并发。
- 任意必要环节缺失时，结论只能是 `部分打通`、`仅 mock` 或 `待后端接入`，不能声称功能已经完整支持。
- 前端先行可以完成目标契约和隔离实现，但交付说明必须区分真实能力与待接入部分；产品界面是否展示工程态说明服从项目产品规则。
- 只有本地缓存、预览页、mock adapter 或临时成功状态可见时，禁止表述为真实入库、真实回显或端到端完成。

用户要求审查、提交前检查或判断完成度时，输出字段事实表或等价证据、断链位置、风险等级、当前状态以及必须补齐的代码或文档。普通实现任务可在内部完成追踪，只在收尾说明关键证据和剩余风险。
