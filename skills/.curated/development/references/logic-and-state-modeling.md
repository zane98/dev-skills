# 复杂逻辑与跨层状态建模

用最小可审查模型固定权威事实、不变量与失败语义。建模服务于设计与实现，不因高风险关键词自动生成完整文档体系。

## 触发与深度

新增或改变跨层多状态、多个主体/来源共同决定结果、并发、异步回调/补偿、资金或权限等关键语义时，先检查已有权威契约。明确恢复既有行为的 bug 可直接按契约修复；简单 CRUD、纯样式和局部内部重构不触发完整建模。

- 局部边界可用简短事实/转换表解释时，直接在对话或已有文档表达。
- 多系统、独立生命周期或复杂分支难以用短表审查时，增加必要的状态、逻辑或资金流图。
- 用户明确要求 HTML 或需要可独立打开、持续维护的复杂模型时，使用下方 HTML 产物；不以图表数量判断模型质量。

## 建模顺序

1. 从产品定义、代码、测试与实际数据区分事实、推断和待决项；先写出最简单可行方案，再解释额外机制维护什么真实约束。
2. 区分独立事实轴，为每个轴明确身份、含义、权威来源、写入者与消费方。不同所有者的事实不能压成一个 status，纯派生显示也不应反过来成为新的权威状态。
3. 列出不变量与关键转换：当前状态、事件、条件、原子变化、外部副作用、下一状态、幂等身份与失败恢复。非法转换由服务端拒绝。
4. 将必要事实映射到 API、存储、任务/外部结果和用户可见投影；刷新、换端、重放后仍须得到同一语义。规则多时用 INV/AXIS/TR 等稳定 ID，简单模型不强制编号。
5. 按适用风险判断拒绝、超时/结果未知、重复/乱序、并发、中断、部分成功与恢复；只展开会影响本次行为的场景，不生成逐项 n/a 的长清单。
6. 删除重复状态、可避免的同步、无实际消费者的投影和无法说明业务差异的分支；检查删减后是否仍满足关键不变量。对剩余复杂度说明简单方案为什么不足，再完成必要图表。

图、表和文字需一致；未知外部结果保持可查询、可重试或可对账，不能由前端默认成功或错误兜底覆盖。

## 资金与外部副作用

- 分别识别实际存在的业务资格/订单、支付结算指令、已入账账本、渠道执行和到账/退回事实；业务标签、渠道成功和银行到账不能互相代替。
- 每一跳明确付款/收款主体、金额、币种、精度/舍入、费用、净额和生效时点，用金额等式证明守恒；区分可用、锁定、在途和已退回。
- 业务 ID、动作幂等键、账本来源和渠道尝试/回调身份必须可关联；一对多/多对一有明确分配或聚合规则。
- 明确事务与外部调用边界，覆盖渠道可能成功但响应超时、外部成功本地提交失败、入账后通知失败、重复/乱序和适用的退款/退回；通知失败不能回退已经发生的资金事实。
- 完成结论分别列出业务、账本、渠道和实际到账/退回的直接证据。对账按身份、金额、币种与批次/时间关联；修复入口须可 dry-run、幂等、可审计且有停止条件。

## 确认与实施

- 行为契约存在关键歧义，或方案将改变用户已确认的业务结果、金额、权限和恢复规则时，先列明待决项并取得决策；其依赖实现保持 Draft。
- 用户已确认同一契约，或现有授权已清楚覆盖行为与取舍时，直接实施，不额外要求确认排版、建模格式或同义重述。纯工程选择且不改变行为时由 agent 决定。
- 每条关键不变量和转换要有执行所有者：领域约束、数据库/事务、外部边界、API 与必要消费端。先实现权威事实与高风险边界，再接消费端。
- 验证需求从模型派生；编写或运行按 [执行边界](execution-boundaries.md)。测试与模型冲突时判断契约和证据，不能一边改实现一边把判定标准改到通过。

## HTML 产物

确需独立产物时沿用项目设计/RFC 目录；无约定可用 docs/design/<topic>-logic.html。从 [模板](../assets/logic-state-template.html) 裁剪为一个自包含 HTML，删除空章节，不依赖 CDN、在线字体或服务。

包含本次需要的范围/假设、事实与不变量、跨层映射、转换/异常、必要图表和待决项；资金任务补金额等式与对账关系。直接嵌入可见 SVG/CSS 图并保留可编辑图源，节点短标签、正文可读、小屏图表可滚动，颜色不作为唯一信息。

标记契约版本和状态；长期事实按 [文档同步](product-code-sync.md) 指定权威来源。只读审计不自行写仓库，除非用户要求产物，否则在回复中给出等价模型。
