# 开发现场生命周期

`development` 决定是否需要现场并维护任务归属；本地清理由 `$commit` 负责，平台合并和远端 head 清理由 `$merge-pr` 负责。开发完成、代码合并、现场清理是三个独立事实。

## 先复用，必要时创建

- 静态审计、方案和可在当前 checkout 安全完成的单点修改，不另建 branch/worktree。需要 Git 交付时按仓库规则使用任务分支，分支不必另配 worktree。
- 创建前核对当前 diff、分支、`git worktree list --porcelain` 与已知活跃 owner；有 app artifacts 工具时核对本任务附件。优先复用本任务已有且基线合适的现场，不接管其他任务。恢复任务、切换 skill、压缩上下文或重试本身不构成新建理由。
- 当前 checkout 存在无法安全隔离的 WIP、确需独立写入流、冲突集成或不同版本运行隔离时才新建，并说明具体理由。每个独立写入流默认一处现场；重用时核对起点和原改动，不 reset 未交付内容。只读子 agent 不因并行就各建一个 worktree。
- 创建或明确接管时，立即在当前对话/已有交接上下文记录 repo、目标分支、branch/worktree 路径、owner、用途、起始 SHA 和预计去向；managed worktree 另记 attachment identity。主 agent 汇总子 agent 返回的现场。不要为此新增开发计划任务或另一套日志系统。

## 同一任务接力到底

交给 `$commit`、`$merge-pr` 或 `$resolve-issue` 时传递完整任务资源清单、已有授权、交付组与有效验证，不只传当前 cwd 或 PR URL。接力方显式接管，原 owner 和子 agent 结束写入后才进入删除判断；流程返回时核对所有资源，不能把未清理项从记录中消失。

## 结束、暂停与交接

| 当前事实 | 处理 |
| --- | --- |
| 已授权完整 Git 交付 | 沿既有交付链推进到合并、目标同步和任务收口，复用其结果；有多个交付组时不在组间删除后续组现场 |
| 仅完成实现，或用户限定停在 commit/PR | 保留恢复所需的最少现场，明确尚未合并及下一步；清理有证据证明已被替代的临时副本，不丢弃唯一成果 |
| 无代码成果的临时审计/验证现场，或本任务已交付的残留 | 在 owner 已释放、内容已交付/等价或用途明确结束后，调用 `$commit` 的“仅清理”模式，只处理本任务；该调用不授权 commit/push/PR/merge |
| 交付或清理受阻 | 保留所需成果，报告具体停点、路径、owner 和恢复条件；不能将已合并分支仅因“用户没要求删”永久留置 |

本地删除、managed archive、指纹与 scope manifest 均遵循 `$commit`，不另写删除命令。已授权交付链中的资源由其最终收口一次处理；没有可清理项时直接说明保留状态，不重复调用。

收尾按本任务输出简短表格或列表：`分支/worktree | 合并状态（目标、PR/MR、合并 SHA 或尚未合并） | 现场状态（已删除/已归档/保留及原因）`。不在 Git 仓库中时省略；没有新建现场时一句说明即可。其他任务现场保留，不为本任务报告做全仓清零。
