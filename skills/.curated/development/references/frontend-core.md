# Frontend Implementation

实现页面、组件、数据交互、表单、权限、路由、状态或质量保障时，使用本参考。

## 复用与模块归属

- 新增前搜索定义、导入、使用点和测试；优先复用项目已有组件、hooks/composables、services 和工具，再使用当前技术栈成熟能力。
- 只有语义、输入输出、错误和边界行为一致时才复用；名字相似但业务规则不同就保持分离。
- 纯数据转换放领域工具模块；状态与生命周期行为放 hook/composable；远端交互放 service/数据层；平台差异放 adapter。
- 共享代码先靠近使用方，出现稳定语义或真实重复后再提升层级；不要建立无归属的 `utils`、`helpers`、`common`。
- 新工具函数保持职责单一、输入输出清楚且尽量纯；不要用薄包装改名标准库或成熟库已有能力。

## 组件化

- 页面/路由层负责解析路由、业务编排和页面级状态；业务组件承载业务语义与完整交互；基础组件只表达通用 UI 能力。
- 满足任一条件再抽取：同一语义真实复用、复杂交互/状态可独立、存在清晰测试或替换边界。一次性薄包装和只转发 props 的组件留在原处。
- 把数据获取放到真正拥有 loading、empty、error、refresh 全生命周期的最近稳定边界，不让每个叶子组件自行请求。
- 业务组件优先接收业务对象或内聚 view model 与意图回调；不要传一串散字段，也不要把内部布局暴露成微参数。
- 结构变化使用 children/slot/组合，有限视觉或行为差异使用 variant；布尔参数开始组合出多种模式时，拆成明确 variant 或独立组件。
- 共享组件覆盖实际适用的正常、loading、empty、error、disabled 和 permission 状态，并保持焦点、键盘和触控行为完整。
- 跨平台差异收口到适配组件或能力层，业务组件不散落平台判断。

## 请求与数据

- API 请求走项目统一 service 和 query/cache 层；复用已有鉴权、错误转换、取消、重试和通知机制，不在页面另写一套。
- query/cache key 包含真正影响结果的路由、筛选和身份参数；参数变化驱动请求，不靠副作用手工同步。
- 请求层拥有 loading、error、cache、retry 和 stale 规则；页面只组合稳定状态，不用生命周期重复封装。
- mutation 成功后按业务实体和查询参数精确更新或 invalidate；乐观更新必须能失败回滚，并处理并发覆盖。
- 按首屏和用户路径拆分请求，必要时使用分页、懒加载、预取或后端聚合；不要一进页面拉取全部可能数据。
- 权限、金额、业务状态和对外口径等事实由 API 提供；缺接口时先明确契约并标记 `pending-backend`，mock 只用于测试或隔离开发。

## 路由

- 集中使用项目路由定义和参数类型，不在组件中散落路径字符串、重复解析或手拼未编码参数。
- 路径、search params 承载可分享、可刷新、决定结果的状态；弹窗开关、hover、临时输入等留在局部状态。

| 用户意图 | 路由语义 |
| --- | --- |
| 进入新的可返回流程 | `push` / 普通页面跳转 |
| 修正默认参数、登录落地或替换中间态 | `replace` / 重定向 |
| 回到真实上一页 | `back`，不伪造目标 |
| 进入 tab、根页面或重建流程 | 使用平台专用 API |

- 守卫只消费统一认证/权限事实，保留合法原目标并避免重定向循环；未登录、无权限、不存在和不可见必须区分。
- 冷启动、深链、分享页不能假设存在历史栈；校验参数和资源后提供稳定落点或明确主页入口。
- 提交成功后的缓存更新、关闭和跳转顺序必须明确，避免跳走后旧数据闪回。

## 状态归属

| 状态类型 | 唯一所有者 |
| --- | --- |
| 可分享、可刷新、决定页面结果 | URL / 路由 |
| API 数据、请求状态、缓存和重试 | 项目统一服务端数据层 |
| 字段值、校验、dirty、提交状态 | 表单体系 |
| 瞬时交互和单组件状态 | 组件 / reducer |
| 真正跨页面、跨组件且由客户端持有 | 项目共享 store |

- 不把 query 数据、props 或可计算值复制到 store；派生值在读取处计算，避免双向同步。
- 共享 store 保持最小，只暴露业务动作和稳定 selector；复杂且受事件驱动的状态流再使用 reducer/state machine。
- 只有明确需要跨会话恢复时才持久化，并处理版本、过期、退出登录清理和账号隔离。
- 页面重新展示或恢复时，根据数据时效和缓存状态刷新，不无条件重拉或手工同步多份状态。

## 表单、权限与反馈

- 明确表单 schema、默认值、字段语义和提交 payload；字段错误放字段附近，服务端字段错误不得吞成泛化 toast。
- 菜单、路由、按钮和接口错误统一使用服务端或项目权限层的事实，不在页面临时拼权限规则。
- loading、empty、error、success、warning 和重试使用项目统一反馈；稳定页面错误位才进入布局，避免临时错误块造成跳动。
- 交互控件提供适用的 disabled、loading、focus 和错误状态；弹窗、抽屉和菜单处理焦点、键盘、关闭与遮罩行为。

## 安全边界

- 不可信内容默认按文本渲染；确需原始 HTML 时使用项目认可的 sanitizer，并禁止 `eval`、字符串脚本和未审查的 DOM 注入。
- 客户端包不得包含秘密；敏感凭证和业务数据不进入 URL、日志或非必要持久化，沿用项目认证/CSRF 策略并在退出时清理用户态缓存。
- 校验外链协议、重定向目标、上传文件和第三方脚本边界；前端可见性不是授权，敏感操作仍由服务端校验。

## 性能与资源

- 沿用项目性能预算并先测量再优化；按路由/功能拆分代码，懒加载非首屏能力，使用项目图片、字体和静态资源方案。
- 长列表使用分页或虚拟化，昂贵计算避免进入高频渲染；只有测量证明有价值时才 memo，不能用缓存掩盖错误状态设计。
- 清理监听器、定时器、订阅和未完成任务；为图片、媒体、骨架屏和动态内容保留稳定尺寸，避免布局跳动。

## 响应式、可访问性与可靠性

- 使用项目 breakpoint、容器和安全区规则，验证支持视口、缩放、软键盘及长文案/动态内容，不允许溢出、遮挡或不可操作。
- 优先原生语义；表单控件、图标按钮和媒体提供可访问名称、label、alt 或字幕，避免用 ARIA 修补错误元素。
- 保持键盘顺序、焦点可见与弹层焦点管理；满足对比度、触控目标和 `prefers-reduced-motion`，重要错误/状态变化可被辅助技术感知。
- 项目已有 i18n 时复用其文案和日期/数字/时区格式化，不拼接可翻译句子，也不假设文本长度固定。
- 页面/路由渲染失败使用项目 Error Boundary/错误页提供降级和重试；接入已有错误上报并过滤凭证与敏感数据。

## 验证

| 变更 | 优先验证 |
| --- | --- |
| 工具函数、派生逻辑、reducer | 单元测试与边界输入 |
| 共享组件、表单、交互 | 组件交互/可访问性测试，已有时同步 Storybook/视觉快照 |
| 请求、缓存、路由、状态协作 | 集成测试，覆盖成功、空、错、竞态和恢复 |
| 关键业务流程或目标平台能力 | E2E 或最小 smoke |
| 样式、token、响应式 | 关键视口和主题截图/视觉走查 |

- 检查组件/工具复用、模块归属、请求入口、状态所有者和 design token；按风险执行最小充分检查，涉及安全、性能或可访问性时运行项目已有专项工具并记录未覆盖风险。
