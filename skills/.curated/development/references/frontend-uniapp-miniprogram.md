# uni-app Mini Program

用于基础框架或现有项目已选择 uni-app 的小程序任务。

## 栈内边界

- 从 `pages.json`、`manifest.json`、构建配置、入口和 Provider 识别 Vue、TypeScript、组件、请求、状态及目标平台，并沿用现状。
- 只实现需求包含的平台；H5、App 和各小程序端的能力与样式不能默认等价。
- 项目使用 easycom、组件库或原子 CSS 时遵循其目录、命名、主题和目标平台兼容规则，不混搭第二套体系。

## 路由与状态

- tab 页面使用 `uni.switchTab`，普通页面使用 `uni.navigateTo`，替换中间态使用 `uni.redirectTo`，返回使用 `uni.navigateBack`，重建根流程时才使用 `uni.reLaunch`。
- 分享或冷启动页不假设存在返回栈；校验参数和登录态后提供明确落点。
- 请求走项目统一数据层；使用 Vue Query 等缓存层时，key 包含页面参数、筛选和身份上下文。
- 页面可能被保留；根据数据时效决定 `onShow` 是否刷新，不在每次展示时重拉全部数据，也不把请求结果复制进 Pinia。

## 组件与样式

- 按复用语义分层：跨应用共享稳定组件，应用内共享业务组件，单页组件留在页面附近；不同角色、权限或流程只保留薄装配层，不为名字相似强行合并。
- 优先使用项目组件、design token 和现有原子 CSS。样式迁移以视觉、状态和平台行为等价为目标；一次性值不包装成 token，复杂或平台兜底样式可以保留局部 CSS。
- 组件样式优先 class selector；避免标签、ID、属性、结构伪类和依赖真实 DOM 的深层穿透。把 disabled、selected、首尾项等状态显式映射为 class 或 props。
- 原子 CSS 使用静态完整 class 或显式 mapping，不拼接 class 片段。小程序组件存在样式隔离时，关键内部结构保留组件本地 token 样式和必要 fallback；构建后检查规则实际进入目标 `.wxss`。
- 共享组件通过项目公开入口、easycom 或受支持的装配层消费；不要让页面跨包依赖编译器无法稳定处理的源码相对路径。修改共享组件时核对所有消费端及项目已有组件示例。

## 原生控件与导航区

- 普通操作优先使用项目按钮组件；只有开放能力、原生表单或明确平台语义需要时才直接使用原生 `button`。保留原生控件时显式处理尺寸、间距、边框、背景、行高、盒模型和平台伪元素，不依赖默认样式。
- 仅需点击且不需要原生按钮能力时，按项目约定使用 pressable/view 封装，并保留禁用态、触控反馈和可访问语义。
- 自定义导航栏先预留状态栏，再按胶囊按钮位置约束内容行和右侧安全空间；标题、搜索框、tab 和动作不能侵入系统区域。

## 加载与资源

- 页面壳、导航和稳定布局先渲染。无数据时显示骨架，有安全缓存时先展示旧数据并后台刷新；错误不替换仍可用内容，下拉刷新不先清空页面。
- 账号隔离、过期和退出清理是持久缓存的前提；支付结果、强实时状态、一次性授权和敏感表单材料不作为普通展示缓存。
- 小而稳定、首屏高频且受包体预算允许的资源可随包；运营图、频繁替换内容和上传媒体走项目远程资源方案。原生配置依赖的图必须位于当前应用可解析的本地路径，跨应用共享源不等于运行时跨目录引用。

## 平台边界与验证

- 不依赖 `window`、`document`、浏览器 DOM、复杂 selector 或未经目标平台验证的 CSS；平台差异收口到适配层。
- 原生能力区分用户拒绝、平台不支持、系统失败和业务失败，并提供可理解的降级。
- 以目标平台限制和项目 CI 预算检查主包、分包及静态资源；使用按需导入和项目已有 CDN/对象存储。
- 构建用户指定的目标平台并检查产物告警；再 smoke 冷启动、分享进入、路由、授权、弱网、刷新恢复、安全区和关键组件状态。selector、样式隔离或原子 CSS 的验证结论以目标小程序构建产物为准，不能只看浏览器预览。
