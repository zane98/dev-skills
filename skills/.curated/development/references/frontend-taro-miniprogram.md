# Taro Mini Program

用于基础框架或现有项目已选择 Taro 的小程序任务。

## 栈内边界

- 从 Taro 配置、页面配置、入口和 Provider 识别 Taro 版本、React/Vue、TypeScript、编译器、组件、请求、状态及目标平台，并沿用现状。
- 只共享目标平台稳定支持的能力，不假设一次编写即可无差异运行；平台分支集中到配置或适配层。
- 优先使用 `@tarojs/taro`、Taro 组件及项目封装；只有单平台能力明确且已隔离时才调用原生 API。

## 路由与状态

- tab 页面使用 `Taro.switchTab`，普通页面使用 `Taro.navigateTo`，替换中间态使用 `Taro.redirectTo`，返回使用 `Taro.navigateBack`，重建根流程时才使用 `Taro.reLaunch`。
- 分享或冷启动页不假设存在返回栈；校验参数、平台能力和登录态后提供明确落点。
- 请求走项目统一数据层；缓存标识只包含真正影响结果的页面参数、筛选、平台和身份上下文。
- 页面可能被保留；根据数据时效决定页面展示生命周期是否刷新，不重复手写请求状态，也不把缓存数据复制进客户端 store。

## 组件、平台与验证

- 使用 Taro 组件和事件模型，不依赖浏览器 DOM 或未经目标平台验证的 CSS、滚动和定位行为。
- NutUI Taro、Taro UI 或其他组件库沿用项目版本、主题和 token；单平台原生组件用适配组件隔离 props、事件和降级。
- 原生能力区分用户拒绝、平台不支持、调用失败和业务失败，并提供可理解的降级。
- 以各目标平台限制和项目 CI 预算检查主包、分包、插件及资源；避免整包导入组件、图标或工具库。
- 分别构建每个目标平台并 smoke 冷启动、分享进入、路由、授权、弱网和关键组件状态；一个平台通过不代表其他平台可用。
