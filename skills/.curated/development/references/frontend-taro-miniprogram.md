# Taro Mini Program

用于基础框架或现有项目已选择 Taro 的小程序任务。

## 栈内边界

- 从 Taro 配置、页面配置、入口和 Provider 识别 Taro 版本、React/Vue、TypeScript、编译器、组件、请求、状态及目标平台，并沿用现状。
- 只共享目标平台稳定支持的能力，不假设一次编写即可无差异运行；平台分支集中到配置或适配层。
- 优先使用 `@tarojs/taro`、Taro 组件及项目封装；只有单平台能力明确且已隔离时才调用原生 API。

## 路由与状态

- 小程序目标下，Taro 入口组件的 `children` 用于承载页面节点及 Provider，入口本身不渲染页面内容，也不是当前路由的嵌套 layout/`Outlet`；不要把可见登录态或路由分组照搬成 Web App Shell。
- 以 H5 为交付目标时显式配置 `h5.router.mode`；生产默认选择 `browser` 并配置 SPA fallback，只有托管环境无法回退入口文件时才保留 `hash` 并说明原因。未以 H5 为目标时不为此改动小程序路由。
- 有现成声明式路由时优先使用其守卫或受保护 layout；没有时用页面 export 外层的统一 wrapper/HOC 表达准入策略，确保认证通过前不挂载包含 hooks、查询和副作用的页面内容。不要在页面函数执行后才用组件包住返回 JSX。
- 所有页面策略一致时才在入口统一阻断；公开与受保护页面混合时，入口只维护会话和 Provider，公开页面直接渲染，受保护页面在各自注册/export 边界声明策略。
- `Taro.addInterceptor` 是请求拦截器，不是路由守卫；封装 `navigateTo` 等导航 API 也不能覆盖冷启动、分享进入和 `switchTab`，只能作为页面准入之外的体验优化。
- tab 页面使用 `Taro.switchTab`，普通页面使用 `Taro.navigateTo`，替换中间态使用 `Taro.redirectTo`，返回使用 `Taro.navigateBack`，重建根流程时才使用 `Taro.reLaunch`。
- 提交成功进入结果、进度或详情页时检查整个页面栈：单页表单通常用 `Taro.redirectTo` 替换自身；“填写 -> 确认 -> 结果”链路不能只替换确认页，否则填写页仍会被返回命中。可由确认页通过 EventChannel 通知填写页，先返回再让填写页替换自身，或使用项目已有且经运行态验证的等价退栈方案。
- 分享或冷启动页不假设存在返回栈；校验参数、平台能力和登录态后提供明确落点。
- 请求走项目统一数据层；缓存标识只包含真正影响结果的页面参数、筛选、平台和身份上下文。
- 页面可能被保留；根据数据时效决定页面展示生命周期是否刷新，不重复手写请求状态，也不把缓存数据复制进客户端 store。

## 组件、平台与验证

- 使用 Taro 组件和事件模型，不依赖浏览器 DOM 或未经目标平台验证的 CSS、滚动和定位行为。
- NutUI Taro、Taro UI 或其他组件库沿用项目版本、主题和 token；单平台原生组件用适配组件隔离 props、事件和降级。
- 原生能力区分用户拒绝、平台不支持、调用失败和业务失败，并提供可理解的降级。
- 以各目标平台限制和项目 CI 预算检查主包、分包、插件及资源；避免整包导入组件、图标或工具库。
- 分别构建用户指定的目标平台；再 smoke 冷启动、分享进入、路由、授权、弱网和关键组件状态。一个平台通过不代表其他平台可用。
