# API 契约

## 协议与所有权

- 明确调用方、业务动作、可信身份与数据所有者；参数和输出定义类型、必填/默认、空值、枚举、单位和安全字段投影。
- 沿用项目分层：协议边界负责校验、鉴权与传输转换，领域拥有业务规则，存储层拥有持久化细节。按复杂度分离职责，不为每个简单接口强制增加 service/repository/mapper 文件。
- 写动作按业务身份定义幂等和冲突，尤其关注创建、支付、回调、导入和任务重放。公共字段、默认行为与错误语义变化需考虑旧调用方兼容。

## 错误契约

- 领域错误保留分类和根因，只在 API 边界映射 status、业务 code 和公开 message，三者语义一致。
- 参数、认证、权限、不存在、冲突和限流等按既有契约返回，未知异常才用通用系统错误；下游内部状态和消息不直接透传。
- 既有 200 + 业务 code 协议保持兼容，但不得把失败写成成功；协议迁移独立处理。响应提供项目追踪标识，日志保留必要错误链并避免泄露 SQL、路径和秘密。
- 错误映射变化验证真实响应，不能只断言 service 返回 error。

## 查询与分页

具体成本、索引、关联粒度和数据库约束见 [数据建模](backend-data-modeling.md)，这里定义对消费者可见的选择：

- 有稳定业务硬上限且整体成本可接受的集合可以全量返回；超出假设不能静默截断。可增长数据、昂贵响应或局部消费采用服务端分页。
- 需要随机跳页且偏移成本可控时使用 page/offset；连续浏览、大数据或频繁更新时考虑 cursor/keyset，沿用项目契约而非统一换型。
- 排序稳定并用唯一字段打破并列；筛选与排序在分页前生效。cursor 绑定筛选/排序语义，明确方向、过期/非法处理和 hasMore。
- 页大小有默认值与硬上限；导出、同步和批处理使用有界批次、流式或专用任务，不靠超大 pageSize。
- 只在用户确需时计算精确 total；昂贵计数可以用 hasMore、明确标识的近似值或独立统计，UI 不伪造总数。
- 定义空结果、末页/越界、筛选变化后的重置、刷新/返回恢复及缓存兼容。排序字段使用白名单；查询形状需可接受。
