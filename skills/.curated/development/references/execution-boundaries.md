# 执行边界与长任务恢复

基本授权与验证原则见 [Development](../SKILL.md)。本文件用于组合请求、执行受阻和交接；其他 reference 的检查项目不能扩大当前任务。

## 判断范围

| 请求 | 执行范围 |
| --- | --- |
| 检查、审计、诊断 | 默认先静态读取、报告根因与影响，不改实现或业务数据；请求包含运行验证时执行对应隔离检查 |
| 只给方案或计划 | 提供可决策结果；用户要求保存产物时可写指定文档，不自动实现 |
| 实现、修复、重构 | 修复目标及过程中可安全处理的缺陷，完成必要验证；不因历史问题或跨模块另行索要授权 |
| 测试、验证或验收 | 运行对应检查，定位并修复发现的问题后复验；只运行必要检查 |
| 明确只测试、不改代码或只报告 | 保持只读限制，运行获准检查并报告缺陷；不把它套用到普通测试或开发中的验证阶段 |
| 写测试、补覆盖 | 实现必要测试资产并验证其能区分正确与错误行为 |
| 完整交付或部署 | 由相应 skill 继承用户授权、范围、版本和已有证据；不重复执行已有效的验证 |

本地可逆检查可复用项目标准运行环境；先确认服务、端口和输出目录所有者。共享 dev/watch 与 build/test 争用产物时隔离或串行，确认新产物已加载再取运行证据。无法使用目标环境时，替代检查只证明其覆盖范围。

编写 migration、修复权限或金额计算代码、隔离测试均可属于正常修复；触及这些文件不等于执行生产迁移、真实扣款或变更线上权限。部署、业务数据写入和对外通知只按已有授权执行；尚未授权时把确认留在具体外部动作前，不阻塞代码、脚本和隔离验证。故障注入、压测或不可逆写入须有明确环境、范围与停止条件。

## 受阻与恢复

- 检查失败先定位实现、契约、依赖、环境或资源竞争，必要时比较同版本基线，再直接修复代码、测试、fixture 或本地环境并重跑受影响检查。历史失败、hook/CI 报错和可修复冲突是待办，不是授权闸门；不通过跳过检查、删除有效断言或改写业务契约让结果变绿。相同尝试不再提供信息时换路径，只有缺少必要输入或实际权限且没有安全替代时才报告具体阻塞。
- 若 skill 导致暂停或未完成，链接实际读取的 SKILL.md 和相关 reference，引用触发规则并解释适用范围；先判断用户是否已授权，不把自己的推断包装成强制审批。
- 长任务只保留目标、范围、所有者、已完成、下一步、有效验证及失效假设。优先复用对话/已有计划，不额外建立日志体系。
- 压缩或交接后恢复最新用户指令与相关文件/Git 状态；新问题默认用于调整当前任务。只有明确停止、取消或替换目标才放弃原任务，局部改变仅使依赖旧假设的工作失效。
- 合并、部署、数据操作或通知前重新读取必要可变状态；复用的证据应对应具体版本、范围和环境。
