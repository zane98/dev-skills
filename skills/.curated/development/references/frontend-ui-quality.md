# 审美校准与验收

用于 UI 质感受质疑、学习优秀案例或视觉改进；一处已知间距/遮挡修复直接复用规范并验证，不默认做参考研究。组件与 token 规则由 [Design token](frontend-design-token.md) 管理，浏览器状态与证据由 [前端核心](frontend-core.md) 管理。

## 先定任务，分别判断

- 选一个真实任务与代表页面，说明用户要找什么、判断什么、完成什么；核对现有品牌、组件、Token、Layout 和样板。区分“违反已有规范”与“规范内仍不好用/不好看”，分别列依据，合规不是审美合格证。
- 先处理当前任务最明显的一两处问题，在同一页面验证；复杂任务再增加关键页面/状态，不要求先重搭设计系统。保留有效信息、操作、品牌与技术栈，不用精简隐藏必要内容。

## 注意力、分组与操作位置

- **先分配视觉权重。** 当前内容、关键判断与主要动作先被看到；用于定位的导航、页头和辅助元信息随后。检查字号、字重、图标、底色与强调色是否都在争抢视线；只降低无关强调，保留可读对比、选中态、错误与键盘焦点，不把整块导航设为半透明。
- **分隔表达关系。** 每条边框/分隔线应帮助识别分组、独立滚动区域或必要交互边界；如果已有留白、对齐或表面层次能表达同一关系，去掉重复画线。表格列/行辨识、字段边界、弹层层级与焦点轮廓可以保留；不以“零边框”作为目标，也不靠拉大间距牺牲任务密度。
- **强调按状态赚取。** 避免每个图标都带底色、每块内容都套卡片、每段元信息都用强对比；装饰降噪，承载识别或异常含义的信号仍清楚。按默认、hover、selected、focus 与错误态分别判断，不能靠全部降亮度制造安静。
- **动作位置可预测。** 同类视图的导航、视图控制和内容操作各有稳定归属；分享、复制链接、更多等相同语义动作沿用一致位置。用上下文减少常驻动作时，保留键盘、触控与可发现入口；先复用已有页面模式，不为借鉴案例强行增加双层页头或换导航结构。

## 轻量参考学习

1. **同任务选案例。** 从可访问的真实产品、官方示例或用户给定参考中，选少量能解释当前问题的案例，记录来源/页面、目标用户、任务、设备与密度及不匹配点。后台表格对照同类查找/筛选/批量任务，复杂表单对照同类录入/复核流程；不拿营销 Hero 当高密度业务页标准，不混抄不同风格。没有可验证案例时说明缺口，先用现有相邻页面与规范，不能虚构观察。
2. **拆结构与视觉规则。** 按上节标注注意力、分组与动作归属，再比较阅读顺序、密度、留白、对齐、字体组合及状态反馈。解释这些选择如何帮助任务，以及哪些内容不适合本项目；“高级”“清爽”不能作为修改理由。
3. **提炼可解释规则。** 写成“在什么任务/密度下，用什么规则，改善什么问题，如何沿用当前系统”。例如：同组筛选使用同一 size 和基线，组间留白大于组内，便于识别条件与动作；具体值映射现有 token。迁移结构与规则，不照抄品牌资产、字体、色值或无关装饰；参考不是自动认可的设计或测试基线。
4. **应用一个局部再对比。** 固定同一任务、数据量和窗口，先修改一组工具栏、一个信息区或一种文字层级；再换真实长中文、空值和相关状态，比较前后是否更易读、主要动作是否更易找到、信息量与操作效率是否受损。不得通过删数据、换短文案使截图假好看。效果不成立就回退该尝试，不继续堆装饰；验证有效后才推广到确有同类语义的组件/页面模式。

不要求每次输出研究报告；在已有任务记录、PR 或交付中简记“任务/页面与来源 → 观察 → 采用/拒绝的规则及理由 → 局部变化 → 对比结果与缺口”。参考来源与观察不足时不把假设写成事实。

### 可选学习入口

按当前任务选读，不必全部研究；只借鉴可解释的规则，具体参数映射本项目并用中文内容验证，不直接照搬英文参数或要求采用对应组件库。

| 当前问题 | 参考与观察点 |
| --- | --- |
| 工作区视觉竞争、分隔过量、动作位置不一致 | [Linear 界面改版复盘](https://linear.app/now/behind-the-latest-design-refresh)：对照内容与导航的权重、必要边界及操作位置的可预测性 |
| 数据表密度、对齐、筛选与批量操作 | [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：拆表格、工具栏与操作状态的职责 |

## 验证与渐进沉淀

- 复用已有检查验证规范，在目标浏览器、尺寸和真实内容下验证显示与任务路径，按 [前端核心](frontend-core.md) 选择相关状态。对比首要信息与动作是否更易找到、分组是否仍清楚、密度与状态识别是否受损；截图用于比较具体问题，人工判断保留。若未进行目标用户检验，称为任务走查，不能宣称用户已认可。
- 记录检查做了什么、没做什么；构建、静态扫描、视觉对比和任务操作分别报告证据。无法运行目标页面时，交付可做的静态检查并明确尚未完成 UI 验收。
- 从实际失败逐步更新项目已有样板、规范或回归案例：保留触发条件、错误表现、有效修正和适用边界；临时假设不升格为全局规则。全局 skill 的长期改进遵守其维护流程，不为每次小修新增文档体系。

维护本参考时用 [注意力与必要边界案例](../evaluations/attention-hierarchy.json) 回放；只向评估上下文提供 prompt，隐藏判定字段，再审查实际决策与副作用。
