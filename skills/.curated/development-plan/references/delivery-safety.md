# Delivery Safety

仅在开发涉及破坏性 schema、不可逆数据、订单/支付/金额、认证权限、第三方关键链路或高影响恢复机制时加载。本 reference 只定义仓库内需要实现的安全产出；生产执行步骤不进入开发计划。

## 代码侧迁移安全

- 实现旧状态与新状态的兼容窗口，明确支持的前后版本组合。
- 将 schema 兼容、数据回填、读写切换保护和旧逻辑清理拆成真实代码任务。
- 为重复执行、中断续跑、部分失败和脏数据实现幂等、checkpoint、补偿或拒绝策略。
- 不可逆步骤提供备份/恢复工具或前向修复能力；备份窗口和人工操作写入 Runbook。

## 运行安全产出

- 在代码中实现配置校验、feature flag、健康检查、结构化日志、指标和必要审计。
- 为新旧版本并存定义向后兼容 contract；不能兼容时实现明确的启动拒绝或迁移 guard。
- 将可重复的 smoke、migration check 或恢复工具作为仓库产出实现并维护。
- 发布顺序、灰度范围、流量门槛、观察窗口和决策人属于 Runbook/发布系统，不创建 `REL-*` 开发任务。

## 恢复能力

- 实现可判定的降级、停用、前向修复、补偿或兼容回退路径。
- 数据不可回滚时，不伪造一键 rollback；让工具和日志足以定位与恢复。
- 隔离环境演练是 `$development` 的执行验证，不是计划任务或计划阶段；结果写在交付说明、PR 或 CI，不回填计划。

## 边界

- 开发计划可以包含 migration、guard、feature flag、metrics、recovery tool 和相关测试资产的实现任务。
- 开发计划不得包含生产发布、人工 smoke、灰度扩大、线上监控、备份确认、发布审批或观察期。
- 用户要求执行生产交付时，使用独立 Runbook 或相应部署 skill；该流程不改变已完成开发计划的状态。
