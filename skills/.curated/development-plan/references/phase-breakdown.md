# Phase Breakdown

## 分层

- 边界层：目标、成功标准、角色、已知事实、假设、待确认项、非目标。
- 契约/API 层（如涉及）：协议、字段、错误码、权限、隔离 mock、兼容性。
- 后端层：数据、服务、任务、缓存/队列、权限、日志、测试。
- 前端层：用户端、管理员端、员工端/其他角色端、状态、交互、异常反馈。
- 联调层：接口联调、权限验证、端到端流程、回归风险。
- 迁移发布层（高风险时）：迁移、发布顺序、灰度、观测、回滚、恢复验证。
- 验收层：验收清单、未完成项、风险、上线或下一阶段。

## 多端检查

- 用户端：用户能否完成主流程，空态/错态/加载态是否自然。
- 管理员端：是否需要配置、审核、管理、查看数据或处理异常。
- 员工端/其他角色端：是否有操作入口、处理队列、通知或权限变化。
- 分享页、详情页、列表页、通知入口和回退路径是否受影响。

## 权限检查

- 角色是否新增或变化。
- 页面入口是否受限。
- API 是否校验接口权限。
- 数据是否需要按归属、部门、角色或状态限制。
- 关键操作是否需要审计记录。

## 阶段依赖

- 涉及跨端 API 时，稳定契约是后端和前端并行的前置条件。
- 后端数据模型影响前端展示口径时，要在 API 阶段暴露。
- 前端多端可以并行；涉及 API 时必须共享同一契约。
- 联调必须覆盖至少一个主流程和关键异常流程。
- 不按文件目录或团队边界伪造依赖；能通过稳定契约解耦的任务明确并行。

## 阶段门槛

- 边界完成：成功标准可验证，关键分歧已决策，其余不确定性已记录为可逆假设。
- 契约完成：唯一来源和兼容策略确定，调用方可独立实现或验证。
- 实现完成：输出存在，定向测试或等价检查通过，不把“代码已写”当作 `done`。
- 联调完成：主流程、权限边界和至少一个关键异常场景有证据。
- 发布完成：高风险变更的指标正常，回滚或恢复路径已验证。
- 验收完成：验收清单关闭，残余风险和未完成项有明确归属。
