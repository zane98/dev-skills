# Phase Breakdown

## 实现层次

- 边界：目标、角色、事实、可逆假设、会改变实现的待决策项和非目标。
- 契约/API（按需）：协议、字段、错误、权限、兼容策略和唯一来源。
- 数据/后端（按需）：schema、migration、约束、查询、service、权限、缓存/队列和可观测性代码。
- 前端/客户端（按需）：相关角色端、页面、状态、交互、异常反馈和设计到代码映射。
- 集成实现（按需）：跨模块 adapter、共享类型、事件/同步接线和调用方迁移。
- 长期文档（按需）：PRD、技术设计、Code Map 或稳定契约说明。

验证、验收、人工检查、发布、灰度和线上观察不是开发计划层次。测试代码或可复用测试工具属于实现产出时，放入受影响实现层或独立 `TEST-*` 任务；运行检查留在 `$development` 执行过程。

## 多端影响

- 用户端：入口、主流程、状态和失败反馈需要哪些实现改动。
- 管理员端：配置、治理、异常处理和权限需要哪些实现改动。
- 员工端/其他角色端：操作入口、处理队列、通知和数据边界需要哪些实现改动。
- 分享页、详情页、列表页、通知入口和回退路径是否需要代码调整。

这些内容用于确定实现范围，不在计划中创建人工走查或验收任务。

## 权限影响

- 角色、入口、接口权限、数据权限和审计写入分别由哪个实现任务负责。
- 权限撤销、缓存 purge、幂等和事务一致性落到事实生产方任务。
- 不创建独立“权限验收”任务；必要测试代码随对应实现交付。

## 依赖规则

- 涉及跨端 API 时，稳定契约是并行实现的前置条件。
- 数据模型影响展示口径时，在契约任务中暴露稳定语义。
- 前端多端可并行，但共享同一契约和 design token。
- 多页面视觉工作只在设计到代码映射和共享组件边界稳定后并行；截图与人工对比不进入计划。
- 不按目录或团队边界伪造依赖；只记录实现无法继续的真实依赖。

## 状态推进

- 边界就绪：实现目标和非目标清楚，会改变方案的决策已完成或明确阻塞。
- 契约就绪：唯一来源和兼容策略确定，消费方可以实现。
- 实现完成：代码、schema、配置、测试资产或长期文档产出存在；当前 agent 已按 `$development` 处理必要检查，但计划不记录检查过程。
- 计划完成：所有实现任务为 `done/cancelled`，且没有开发 blocker。

人工验收、生产环境、发布窗口、流量观察或外部审批不会改变以上状态；需要持久化时移交到计划外系统。
