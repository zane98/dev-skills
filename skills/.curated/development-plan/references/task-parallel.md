# Task Parallel

## 状态

- `todo`：实现输出已识别，未开始。
- `doing`：正在实现，或实现相关检查失败后仍需修正。
- `blocked`：缺失会阻止实现继续的开发输入；写清解除条件和责任人。
- `done`：实现输出完成，当前 agent 已按 `$development` 做过必要检查；计划不保存检查证据。
- `cancelled`：范围或方案变化后不再实现；简短记录原因和替代任务。

人工验收、主观视觉确认、生产窗口、灰度、线上观察和外部审批不进入这些状态。

## 任务字段

每个任务的基本字段：

- ID：使用 `API/DATA/BE/FE/CLIENT/TEST/DOC/MIG` 等实现前缀，创建后不重编号。
- 实现输出：要新增或修改的仓库产出。
- 状态：`todo / doing / blocked / done / cancelled`。
- 负责人：负责实现的人或 agent。
- 依赖：实现开始前必须存在的代码、契约、数据或决策。
- 影响范围：主要模块、公共文件或消费者。

按需补充可并行关系，以及阻塞的解除条件/责任人或取消原因；简单任务不必填写这些字段。不要添加验证、证据、截图、验收人、发布窗口或观察期字段。运行现有检查不是任务；新增测试代码、fixture、测试工具或 smoke 脚本是仓库产出时才使用 `TEST-*`。

## 并行规则

- 涉及跨端 API 时，契约稳定后后端和前端可以并行。
- 后端可按数据模型、service、队列/缓存和独立 adapter 拆分；必要测试资产随所有者实现或单独 `TEST-*`。
- 前端可按用户端、管理员端和其他角色端拆分，但共享组件或 token 先确定所有权。
- 同一 migration、schema、公共契约或高冲突文件不得盲目并行；先划分所有权或顺序。
- 不因为任务能分给不同人就判定可并行；只按真实实现依赖和文件冲突判断。

## 子 Agent 调度

先画最小依赖图，再找能同时推进的叶子任务。只有同时满足以下条件才委派：

- 任务依赖已经满足，输入和完成结果可独立描述。
- 子 agent 有足够独立工作量，并行预计比派发、同步和集成成本更省时间。
- 写入路径互斥；或共享边界已有唯一所有者，其他 agent 只读该边界。
- 主 agent 能持续负责协调和集成；即使暂时只需等待，并行后的总关键路径也应预计更短。

不要委派微小修改、强顺序任务、仍在探索核心方案的任务，或会同时修改同一 contract、migration、schema、lockfile、生成物和高冲突公共组件的任务。读代码、定位影响、独立测试和分模块实现通常更适合并行；写密集任务先收窄所有权。

- 从最少数量开始，只开能缩短当前关键路径的子 agent；并发数同时受独立任务数和当前可用槽位限制，不追求占满槽位。
- 一个子 agent 对应一个计划任务和明确 objective；派发后由主 agent 将对应任务标为 `doing`，不默认新增另一套 goal 状态。
- 仅用户或更高层指令明确要求 goal 时使用对应工具；其余任务以 objective 为执行边界。用户未给预算时不设置 token budget。
- 派发内容必须包含任务 ID、objective、输入/依赖、允许修改的路径、禁止触碰的共享边界、必要检查和返回格式。子 agent 只返回结论、改动文件、检查结果和 blocker，不倾倒完整过程日志。
- 主 agent 独占计划文件、共享契约和最终集成；子 agent 不自行改动共享分工。进一步委派只覆盖自身既定任务中的独立工作，沿用允许路径、可用槽位和所有权约束；依赖或共享范围变化时先协调。
- 运行中发现依赖变化或文件重叠时，主 agent 立即发送协调指令、停止其中一方或改为串行；不要依赖最后合并时“碰碰运气”。
- 收集结果后，主 agent 检查实际 diff、契约一致性和风险匹配的验证。只有整合后的实现成立，才把任务标为 `done`；子 agent 自报完成不是完成条件。

派发提示可压缩为：

```text
负责 {TASK-ID}。目标：{可判定的 objective}。
输入/依赖：{已稳定的事实、契约或前置任务}
写入范围：{允许修改的路径}
禁止触碰：{由主 agent 或其他任务拥有的共享文件}
完成条件：{实现输出 + 必要检查}
返回：结论、改动文件、检查结果、blocker；不要扩展范围，报告进一步委派的所有产出与现场去向。
```

## 进度维护

- 每次只更新当前实现任务、状态、开发 blocker 和必要决策。
- 不追加测试计数、命令输出、截图链接、浏览器记录、人工反馈流水或逐轮工作日志。
- 范围变化时更新现有任务或简短记录决策；不要为了保留过程不断创建新 plan 文件。
- 所有实现任务为 `done/cancelled` 且无开发 blocker 时立即归档；后续缺陷创建新任务，不重开旧计划堆历史。
- 总入口只保留状态和实现文件索引；默认单文件计划，不为并行本身拆文件。
