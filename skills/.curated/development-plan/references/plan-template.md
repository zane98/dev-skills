# Plan Template

## 总文档

建议位置：`docs/plans/{feature}/README.md`。把它作为进度和决策总入口；删除不适用内容，不为填满模板制造工作。

```md
# {需求名} 开发计划

## 当前状态

- 最后更新：{YYYY-MM-DD}
- 当前阶段：边界 / 契约 / 后端 / 前端 / 联调 / 发布 / 验收
- 总体状态：todo / doing / blocked / done / cancelled
- 当前任务：{TASK-ID}
- 当前负责人：
- 阻塞项：无 / {原因、解除条件、责任人}

## 目标与成功标准

{一句话说明这个需求解决什么问题}

- 成功标准：{验证对象 + 操作或检查 + 预期结果}

## 边界与假设

- 已确认事实：
- 暂定假设：
- 待确认项：
- 非目标：

## 影响范围

- 契约/API（如涉及）：
- 后端：
- 用户端：
- 管理员端：
- 员工端/其他角色端：
- 权限：
- 数据：
- 缓存/队列：
- 第三方：
- 可观测性：
- 迁移/发布/回滚：

## 任务计划

任务 ID 使用 `REQ-01`、`API-01`、`DATA-01`、`BE-01`、`FE-01`、`QA-01`、`REL-01` 等稳定前缀；创建后不因排序或负责人变化而重编号。

| ID | 任务 | 状态 | 负责人 | 依赖 | 输出 | 验证 |
|---|---|---|---|---|---|---|
| REQ-01 | 确认目标、边界和成功标准 | todo | {owner} | 无 | 已确认边界 | 逐项关闭待确认项，或记录可逆假设 |
| API-01 | 定义契约（按需） | todo | {owner} | REQ-01 | 契约唯一来源、fixture | 契约检查通过，调用方可按 fixture 开发 |
| BE-01 | 实现服务能力（按需） | todo | {owner} | REQ-01 或 API-01 | 代码、迁移、测试 | 指定测试命令退出 0，关键断言通过 |
| FE-01 | 实现端侧流程（按需） | todo | {owner} | REQ-01 或 API-01 | 页面、状态、测试 | 指定场景操作后出现预期 UI 和状态 |
| QA-01 | 联调与回归 | todo | {owner} | BE-01, FE-01 | 测试证据 | 主流程和关键异常场景结果符合预期 |
| REL-01 | 迁移发布（高风险时） | todo | {owner} | QA-01 | 发布、监控、回滚记录 | 指标正常，回滚或恢复验证通过 |

## 并行任务

- 涉及跨端 API 时，契约定稿后后端和前端可以并行。
- 前端多端可拆为用户端、管理员端、员工端/其他角色端。
- 测试用例和验收清单可以与开发并行补充。

## 风险

- {风险}：概率 {高/中/低}；影响 {说明}；触发信号 {指标/现象}；应对 {措施}；负责人 {owner}

## 验收清单

- [ ] 每个 `done` 任务都有输出物和验证证据。
- [ ] API 契约、字段、错误语义、权限和兼容性已验证（如涉及）。
- [ ] 数据一致性、幂等和关键失败路径已验证（如涉及）。
- [ ] 各角色主流程及空态、错态、加载态已验证（如涉及）。
- [ ] 联调覆盖主流程和至少一个关键异常流程（如涉及）。
- [ ] 迁移、监控、回滚与恢复验证完成（高风险时）。
- [ ] 待确认项、未完成项和残余风险已明确移交。
```

## 拆分文件

- `01-api.md`（按需）：接口协议、字段、权限、错误码、兼容性、隔离 mock。
- `02-backend.md`：数据模型、服务、权限、缓存/队列、测试。
- `03-frontend.md`：用户端、管理员端、员工端/其他角色端、UI 状态。
- `04-test-acceptance.md`：联调矩阵、验收清单、回归风险。
- `05-release.md`（按需）：迁移、发布顺序、观测、回滚、恢复验证。
